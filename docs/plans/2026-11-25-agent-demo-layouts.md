# Agent Demo Layouts and Station Trips

Travel Agent starts on a station-specific list rather than automatically attaching to a shared session. A new-trip form offers ten fictional names and ten North American cities; its first message asks for a simulated three-night trip two weeks ahead. Creation records the selections in Workflow memo. Reopening a session never sends that first message again. Up to 50 recent sessions are listed, including ended sessions in review mode.

The launchpad passes its assigned station to the native iframe. Travel Agent validates station IDs 1–4, retains the identity in a path-scoped HttpOnly cookie, and includes it in the owner hash used by API, console, streams, and decisions. The root deployment requires a station through BOOTH_STATION_SCOPING. Shared namespace and queues are unchanged. Old shared sessions remain recorded but are not assigned to all stations. This is a display partition on a public demo, not a private authorization boundary.

Travel and SDLC controls use square, solid Cosmic Pop buttons and touch targets. SDLC bypasses the generic page-shrinking adapter: its story/live view and mission controls occupy separate bounded panels. Failure controls are expandable. The two-row story selector has readable labels. Travel, SDLC, and AgentCore now have distinct architecture maps of their real communication paths rather than the generic six-box loop.

AgentCore uses the normal DemoStage with incident controls on the upper left and compute/history on the upper right. The lower panel includes talking points, a hosted/local-aware architecture diagram, eight SDK examples, and filtered/exact-run Temporal UI. Python snippets are literal source excerpts and follow incident phases. Other SDKs are explicitly illustrative approval/orchestration patterns, not ports of the Strands integration. Its workflow link now includes run ID, which also lets native phase metadata follow the correct run.

Validation: 24 Travel Agent API/context/keepalive tests against an isolated local Temporal server, including all four prefixes, cross-station stream/approval rejection, cookie behavior, memo metadata, and ended-session history. Svelte check passes without warnings. Launchpad tests/typecheck and repository provenance checks pass. AgentCore API Go vet/race tests and all ten Python agent tests pass. The Python tests first lacked network access to download Temporal’s time-skipping test server; enabling that download resolved the infrastructure errors. No paid models or real GitHub mutations were invoked in these checks.

A live local AgentCore check found that the old running worker expected scenario text while the updated API sent an object. Syncing the local worker source recovered the same Workflow. The browser then showed the durable approval wait, eight SDK buttons, a highlighted wait_condition line, and the exact-run UI link. Local execution uses the scripted model; hosted AgentCore availability still depends on the existing Fieldkit platform gate.

The scripted incident recovered after the worker sync, accepted its approval Signal, and completed the same run with five model calls and zero repeated calls. The browser verified the highlighted approval wait and completion steps. No browser restart or new incident was needed to recover that execution. SDLC and AgentCore diagrams were visually reviewed in the full portrait launchpad, and their frame layouts were checked for outer overflow. The actual Mac Mini kiosk/reboot path and a full multi-day soak remain separate acceptance checks.
